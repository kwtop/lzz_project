# DESIGN.md — 图文叙事与网页改版稳定执行版

> **目标：** 用合适的图片吸引阅读，用充分但不堆砌的文字帮助判断，用自然衔接的模块引导理解与询盘。内容丰富不等于文字密集；图片丰富也不等于随意塞图。
> **适用：** 首页、产品分类与详情、解决方案、案例、公司及工厂等展示型页面。新建和改版均执行。
> **使用：** 改动前读取适用的 `AGENTS.md`、本文件和已确认方案。当前明确批准的视觉方案优先于通用视觉偏好；真实性、安全、必要内容和业务功能不得因此被牺牲。

## 1. 五项核心交付要求

| 项目 | 执行标准 |
| --- | --- |
| 页面结构 | 每页 **4–7 个核心模块**，每个模块承担一个清楚的信息任务。 |
| 图片数量 | 每页至少 **3 张不同且合适的内容图片**，实际接入并正常显示；这是最低要求，不是上限。 |
| 图文结合 | **超过一半的核心模块采用图文结合**；参数、FAQ、表单等可不配图，避免连续两块大段纯文字展示模块。 |
| 阅读逻辑 | 先回答访客最关心的问题，再展开细节与证据，最后提供适当的下一步。 |
| 完成标准 | 图片处理、页面实现、真实截图检查和关键功能验证都属于交付，不以写完代码代替完成。 |

**例外限定：** 长篇文章、法规、纯参数页、简单联系页、搜索或工具功能页按实际任务组织，不强凑模块或图片；需在交付中说明理由。普通展示型页面不能因为缺图、时间不足或工具不可用就自动豁免；未达标应标记待补或未通过。

## 2. 先决定页面讲什么，再决定怎么排

- 开始前明确：谁在看、为什么来、最需要什么答案、凭什么相信、下一步做什么。依据现有业务与内容判断，不让用户重复提供项目已有信息。
- 先列模块职责，再写布局。每个模块回答一个主要问题，内部可以包含必要的细节、参数、图片组或子主题。
- **模块计数：** 首屏算一个；有独立职责的正文区、产品网格、参数区、询盘区分别按整体计数。导航、面包屑、页脚、悬浮按钮不算；单张卡片、单条 FAQ 和装饰横条不单独凑数。
- 保留重要信息并合并重复职责；不要为了控制在七个模块内，把全部内容塞进一个巨大模块，也不要删除必要参数和选型说明。
- 同类页面维持稳定的信息骨架，图片与构图按实际内容调整；不同页面类型不强套同一个顺序。

可按页面任务参考以下叙事，而不是照抄成固定模板：

| 类型 | 阅读顺序示例 |
| --- | --- |
| 首页 | 业务与产品定位 → 产品选择 → 应用与适配 → 真实能力证据 → 合作方式 → 询盘 |
| 产品详情 | 产品与关键规格 → 用途和适用边界 → 配置与选型 → 实物细节及价值 → 真实证据 → 询价 |
| 解决方案 | 使用场景与问题 → 解决思路 → 推荐组合 → 实施条件与边界 → 证据 → 联系 |
| 案例 | 客户实际需求 → 方案选择及原因 → 实施或交付过程 → 可核实结果 → 相关产品与下一步 |

模块应承接前面留下的问题；不要用反复出现的口号或“接下来了解……”之类过渡句假装衔接。分类页应尽早展示产品，联系页应尽早提供联系方式，而不是先讲一长段品牌故事。

## 3. 图片必须落实到每一页，不能留到最后

### 3.1 先安排图片位置与来源

修改页面前，为每个核心模块写一行：`模块职责｜核心内容｜视觉形式｜图片来源与处理动作`。纯文字模块写明为何不需要图。这是实施记录，不要把这些说明放进网页。

至少提前落实三张有效图片的用途，尽量覆盖不同的信息任务，例如产品整体、实物细节、应用示意或真实过程。不能把三张近似图片全部塞进首屏，就把后半页继续做成文字墙。

**有效图片计数：** 与当前内容直接相关、清楚可辨、尺寸足以阅读的照片或准确图解均可计入。Logo、图标、背景纹理、占位图、重复图片及近似裁切不重复计数；仅藏在未展开轮播或弹窗中的图片不用于满足最低数量。桌面与移动端正常滚动页面均应看到至少三张有效图片。

### 3.2 每个图片位置必须选择一种处理动作

| 动作 | 适用情况 | 必须执行的工作 |
| --- | --- | --- |
| **保留** | 原图准确、清晰，适合当前内容与构图 | 使用原素材，按版面优化尺寸、裁切和加载。 |
| **润色** | 原图有信息价值，但光线、色调、背景或画幅不理想 | 实际检查原图，使用裁切、调色或可用的 ImageGen 编辑能力改善，保留原图并核对修改结果。 |
| **生成** | 缺少合适的非证据性场景、概念或品牌辅助视觉 | 工具可用时积极调用 ImageGen，生成、检查、筛选后实际接入页面，不只写提示词或建议。 |
| **待补真实素材** | 缺少必须以实拍或真实记录支撑的内容 | 查找项目中可用素材；仍缺失则记录缺口，不用生成图冒充证据。 |

优质原图不必为了“使用 AI”而重生成；低质量或不适合布局的原图，也不能因为已经存在就勉强使用。缺少合适辅助视觉时，应主动制作，而不是默认删掉图片位置。

### 3.3 生图、修图与接入要求

- **生成前先定用途：** 明确图片解释什么、主体是什么、主体位置、横竖比例、文字留白、光线色调及手机端裁切。不要所有图片使用同一构图。
- **摄影风格：** 追求自然光线、合理材质、真实比例与场景细节，避免过度光滑、夸张光效、不合理结构和重复物体。真实摄影风格不等于真实业务记录。
- **编辑前确认原图：** 必须实际读取可用图片文件，不能凭文件名或描述假装修过图。不要把缺失、模糊的关键部件“补画”成未经确认的配置。
- **生成后检查：** 核对主体形态、透视、部件、文字与标识，以及图片是否真正支持本模块。结果不合格就调整或换图，不能因为生成成功就直接使用。
- **实际接入：** 保存最终文件并引用到页面，核对路径、加载、清晰度及两端裁切；按版面提供合适尺寸和压缩，避免堆积超大原图拖慢页面。
- **留下简短记录：** 图片用途、原始来源、保留／润色／生成动作和最终文件路径，统一放在本次改版交付中，不重复创建多套文档。
- **工具不可用：** 如实记录，继续完成可做的素材整理、裁切与排版；缺图页面标记待补素材，未实际生成或编辑不得声称已完成。

## 4. 图片真实，内容也必须可信

- 产品外观、部件、配置、尺寸、性能、标识及技术图解必须依据已核实内容；不能用生成结果反推产品事实。
- 工厂、员工、客户合影、证书、检验、订单、发货和案例结果必须使用真实素材，不生成虚假证据或客户反馈。
- 真实证据图以保守裁切、曝光和色彩调整为主；不得增加设备、改变设施规模、替换客户、修改证书或掩盖缺陷。会改变事实的生成式编辑不得用作证据。
- 应用与通用加工图片用主体、可见特征和用途描述，不添加制作方式或图片类别标签，也不得暗示为本企业已完成的项目。没有证据就删去不实承诺或列为待补，而不是补造事实。

## 5. 图文共同构图，整页统一但不呆板

- 根据图片主体、信息量和阅读顺序安排文字，不先做好一排文字卡片再把图片硬塞进去。主图应足够大，不能以小缩略图陪衬整屏长文。
- 采用适合内容的大幅图片、图上文下、非对称图文、大小图组合、产品网格或过程照片；避免整页机械重复 50/50 左右图文。
- 保持全局字体、色彩、按钮、容器和间距系统一致；统一文字起点、图片边缘及网格对齐，允许局部构图变化，不随意错位。
- 图片要有主次、裁切逻辑和协调的色调，不拉伸、不裁掉关键部件。同组产品保持可比较的比例，不为追求变化打乱产品网格。
- 相关信息靠近，主题转换留出空间；图片、文字和背景的变化形成节奏，不强制每个模块一样高、一样大，也不制造巨大无意义留白。
- 移动端重新检查图文顺序、图片焦点和文字宽度，不只是缩小桌面布局；避免横向溢出、标题断裂、图片遮住文字及按钮难以操作。

## 6. 内容充分，但让人容易读、愿意读

- 先给具体答案，再补充原因、细节和证据。优先讲产品是什么、适合什么、有什么限制及如何选，而不是空泛地强调“领先、专业、一站式”。
- 每个模块保留一个明确主标题；正文按意思分成短段。必要时使用小标题、短列表、参数表或对比表，不把整页变成短口号，也不把长段落全部改成项目符号。
- 正文字号、行高和文本宽度以舒适阅读为准，优先沿用已确认的排版体系；没有规范时可从正文 16–18px、行高 1.5–1.75 起调，不能缩小字体掩盖文字过多。
- 参数、适配条件、选型依据、交付边界和真实证据应足够完整。用结构降低阅读负担，不为“图片多”删掉客户真正需要的内容，也不把关键答案全藏进折叠区。
- 减少无信息量的眉题、解释性小字、重复标语、标签、数字、装饰箭头与按钮；保留必要的语义标题、单位、表单提示及功能图标。
- 内链服务下一步阅读、产品选择或询盘；保留有价值的链接，合并重复推荐，不在每段文字、每张图下机械添加“了解更多”。
- 文案应具体、自然、基于真实业务，不编造采购动机、销量、承诺或案例。每页有清楚的主要下一步，不要求每个模块都放 CTA。
- 关键文字保留为网页可读文本，不烧进图片；保留合理的标题层级、图片替代文本、SEO 元信息和有效内链。不要把 SEO/GEO 理解成堆关键词或重复 FAQ。

## 7. 执行顺序：计划 → 图片 → 页面 → 验证

1. **确认范围和基线：** 读取页面、路由、素材、现有样式和适用规则，保存改前状态，不覆盖用户无关改动；不擅自更换技术栈、批量改 URL 或部署生产环境。
2. **确定模块与图片计划：** 列出每页的模块职责和图片动作，检查是否回答了客户核心问题，是否安排了足够的有效图片。图片计划不能只写“后补”。
3. **落实图片再完成构图：** 可以先搭骨架，但主要视觉布局定稿前必须使用已选定的实际素材，完成必要的修图或生图并接入。
4. **先做代表页再推广：** 批量改版按主要页面类型先完成代表页，自检修正后推广；同类规则复用，图片与内容逐页适配。除任务明确要求审批外，不逐页等待确认，也不擅自把试验方案写成全站规范。
5. **逐页检查内容与图片：** 所有改动页面都检查模块数、有效图片数、图文模块覆盖、引用路径、内容真实性和关键入口，不能只检查一个样板。
6. **真实视觉检查：** 代表页、独特布局页和主要改动页须查看 **1440px 桌面端、390px 移动端**整页截图，并以正常阅读尺度检查局部。大批量同模板页可抽样截图，但必须说明覆盖范围，不能把抽样称为全站视觉通过。
7. **修正并交付：** 修复图片不足、文字堆积、对齐混乱、重复布局和衔接生硬等问题，重新检查；执行构建及导航、内链、表单等关键功能验证，区分静态检查、实际交互和真实提交测试。

## 8. 完成前必须给出可核对的结果

沿用现有交付文件，或集中记录在一份 `docs/redesign-report.md`，不要为每个小动作新增文档。每页至少记录：

`页面｜模块数与职责｜有效图片数｜图文模块数／总模块数｜图片处理与路径｜截图及验证范围｜状态与未完成事项`

- **数量检查：** 普通展示页为 4–7 个模块、至少 3 张有效图片、过半模块图文结合；例外有具体理由，不用重复图片或隐藏图片凑数。
- **阅读检查：** 能迅速认出页面主题，逐步理解适配、价值和证据；没有反复解释同一件事，也没有未回答核心问题就催促询盘。
- **视觉检查：** 图片合适且有信息量，文字充分但不密集，图文关联明确；对齐、留白、层级和两端裁切正常。
- **真实性与功能检查：** 事实不失真，关键内容和链接保留；图片实际加载，询盘路径及已测试功能正常，未测试内容明确注明。

**状态使用：通过／未通过／待补素材／未验证。** 缺少浏览器或截图检查时标记未验证；工具或素材缺失导致数量不达标时标记待补素材，不宣称视觉完成。已完成的代码改造可以交付，但须与最终验收状态分开说明。

> **最终原则：** 不是图片越多越好，也不是文字越少越好。让每张图片有作用、每个模块有职责、每段文字有价值，再用真实页面验证它们是否组合得自然、舒服、可信。

## 9. 当前项目已验证的视觉细则（2026-10-16）

以下细则来自正式页面的实际精修与 1440px / 390px 截图。沿用前述内容真实性与数量标准，不以这些局部经验强制所有页面使用相同排列。

- **字号与网格：** 保留自托管 Inter Variable、常规正文桌面 17px / 1.65、手机 16px / 1.65；政策正文 1.7，行宽上限 70ch。主要容器沿用 1240px，资料/工具页按任务收窄。章间常用桌面 64–80px、手机 48–52px；相关图文通常间隔 24–64px，避免重复 padding 叠加出空洞。
- **入口层级：** 同一文章/零件的图片和标题不必同时链接。优先让具体名称成为入口；必要操作、证件原件和表单提示必须清楚。FAQ 的详细资料按主题集中推荐，答案保持直接可见。
- **技术阅读：** 工艺和报价比较在手机优先给出表格答案，再给辅助示意；保留列标签和全部条件。样件、尺寸、材料、处理、检验、批准及责任不得为缩短页面而删去。流程页分清买方输入、LZZ 确认及放行记录，记录有足够行宽。
- **图像主次：** 产品完整展示主体；辅助 CMM 和新闻细节竖图常用 190–270px 展示宽度，依据内容调整。主图、配对细节和宽幅场景各有职责，不把所有照片铺成同样满屏。真实来访、证件、工厂和包装档案保留原始身份；通用铸坯、材料或记录图片只描述可见内容，不作为订单和检测证据。
- **表单与状态：** 联系方式和字段尽早显示，Message 常用最小 200px；审阅状态的 Subject 标签不拆行，收件人/主题去掉浏览器默认 dd 缩进。校验、复制失败、存储不可用、清除及无 JavaScript 回退属于验收内容。
- **验证记录：** 对同源裁片与响应式版本去重。P04 模糊源不计有效图片，不以缩小展示或插值称为修复。整页缩览、正常尺度局部、几何检查和实际交互须分别记录；文字放大测试说明其具体方式，不冒充操作系统级测试。
