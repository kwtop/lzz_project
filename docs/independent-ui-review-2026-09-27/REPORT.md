# LZZ 当前网站独立前端评审

日期：2026-09-27。对象：http://127.0.0.1:4323/ 。目标：专业、可信、高端。

本报告只依据本次 CUA 浏览器实际页面、保存后重新读取查看的截图，以及当前 DOM 的只读尺寸/状态检查。未读取历史聊天、memory、项目文档、旧截图或源代码。未改网站、未部署、未上传图纸、未发送询盘。仅用 `UI Review / ui-review@example.com` 生成本地草稿，随后通过页面按钮清除测试输入。

## 总体判断和优点

网站已有专业制造企业的视觉基础：黑白灰配红色行动按钮，首页工业大图、统一的零件展示、清楚的产品标题和可读的正文。原始工厂、检测设备、人员照片让企业具有实体感；页脚有直接联系信息和地址；产品目录有筛选及空状态；桌面与手机布局基本成立。

距离“可信、高端”的主要差距在采购判断的信息密度与证据组织，而非缺少装饰。当前经常先展示宽泛能力，再告诉客户具体条件需要另行确认；案例则花较多篇幅解释照片不能证明什么。谨慎是优点，但需要把已知事实和可操作的下一步放到更显眼的位置。

未发现本次路径中的崩溃或无法访问页面。不能据此推断全站无缺陷，也没有验证认证、产能、交期等企业声明本身。

## 收益优先级：正好五项

### 1. 让 ISO 9001 声明有直接、可审阅的证据入口

**观察与证据**：首页首屏直接展示 `ISO 9001 certified`；Quality 的 Certification 区域重复这一声明，展开后仍要求客户联系索取证书详情。该区的 `View company documents` 通向 About，而 About 明确说明展示的是企业认定和教育合作资料，均不是 ISO 证书。本次未看到证书编号、签发机构、范围或有效期。截图 01、18、22。

**客户影响**：客户按认证入口核实，却需要再次联系销售，公开声明与可核验证据之间多了一次交接。真实照片和资质卡片的可信价值因此没有充分发挥。此结论指前端证据呈现不足，不认定企业无认证。

**具体改法**：Quality 设置独立的 ISO 证书卡，展示经企业核实的主体、标准版本、证书编号、签发机构、认证范围和有效期，并提供可放大原件或可下载文件；企业荣誉继续放在 About，名称与入口明确区分。若暂不能公开原件，入口写明“索取 ISO 证书及范围”，不要让“公司文件”承担认证核验入口。

**验收标准**：从首页认证声明或 Quality 的 Certification 入口，一次点击即可到认证信息；用户无需阅读折叠 FAQ 就能分辨质量体系认证与企业荣誉；所有公布字段与有效原件一致。缺失字段明确说明，不能补造。

**性质**：可见信任证据缺口；证书卡片的视觉形式属于设计建议。

### 2. 将“能做哪类零件”变成可用于初筛的工程信息

**观察与证据**：五轴页 `Materials & size` 明确写 machine travel、load 和 maximum part envelope 未公布；Factory 设备区只列设备类别和用途，点击又回到能力页。代表产品详情的材料、表面处理是“可讨论选项”，并非图示零件的已知规格。目录卡片主要由图片和名称组成，客户无法直接比较工艺/材料信息。截图 06、10、13、20、32。

**客户影响**：采购和工程师可以理解产品形状，但难以判断尺寸、材料或检测要求是否适配；需要打开多个页面，再重复提出相同问题。高端制造商的“技术确定性”不够突出。

**具体改法**：在能力概览增加精简的、经核实的工程能力表：设备类别/型号、轴数、加工包络或典型尺寸范围、适用材料、检测手段，以及条件限制。设备页链接到对应能力范围；产品卡显示已确认的工艺标签，产品详情区分“此示例已知信息”和“可选定制范围”。尚无依据的尺寸、公差或材料牌号继续标注待确认，同时列明需提交哪些数据才能判定。

**验收标准**：代表能力页前两个内容区即可回答“适合什么几何、尺寸如何判断、材料如何确认、怎样检测”；Factory 与能力页之间能找到同一份事实信息，而非只有互相跳转；任何示例规格均可追溯，避免把服务选项写成照片事实。

**性质**：观察到的信息缺口与比较负担；表格/标签是展示建议，不表示现有数据足以填满。

### 3. 修复产品到询盘的上下文变化，减少邮件交接的额外工作

**观察与证据**：详情标题为 `Precision machining for complex geometry`，其询盘链接携带 `Ultra-High Precision Machining Services`，询盘正文和生成草稿实际显示后者。表单能正常生成本地草稿，并明确说明需要另开邮件应用、附图、发送；没有站内上传或发送。截图 09、26、27、46、47。

**客户影响**：名称变化让客户怀疑自己是否选错对象；填写网页后仍需在邮件端补充附件和发送，完整任务有一次手工交接。尤其对于仅用网页邮箱的访客，这不如页面上的 `Get a quote` 预期直接。

**具体改法**：使用与详情相同的可读名称，单独展示“参考零件”卡片及返回详情链接，并把详情 URL 放入草稿。不要用产品名称占据用户需求正文。保留现有邮件模式时，在入口写清“准备询价邮件”，把邮箱、复制草稿、保存草稿放在结果区显眼位置；这些后备操作当前已有，应改善层级而非重复开发。只有决定建设实际接收能力后，才另做带附件、错误反馈和接收确认的站内询盘。

**验收标准**：详情、参考卡片和草稿的名称一致，草稿包含正确详情链接；用户填写前能理解页面只生成草稿；生成后能立即找到下一步和不依赖本地邮箱的后备操作。未真实接收时不得展示“询盘已发送”。

**性质**：名称变化是本次实际确认的上下文问题；邮件模式是现有功能选择，不是发送故障；改建站内询盘只是可选产品建议。

### 4. 把工艺案例从“照片来源说明”整理成有图有据的技术解释

**观察与证据**：案例目录开头主要说明照片不是客户案例、检验报告；五轴案例的四段正文和独立 `Source boundary` 侧栏多次解释未知材料、尺寸、客户和验收结果。首屏大照片与下方正文分离，后面的图片区再次展示同一张加工照片。图像已呈现装夹、工件和加工面，但正文缺少与画面对应的标注。截图 14、15、16、37、38。

**客户影响**：来源诚实，但读者花较多精力理解限制，却没有同等清楚地理解 LZZ 的加工思路。视觉上容易像整理档案，难以形成技术团队的专业记忆。

**具体改法**：继续称为“工艺研究”，不虚构客户成功案例。在已有照片上增加简洁编号和对应说明，围绕“可见几何—装夹/刀具访问—需客户确认的检验项”排成图文配对。合并重复边界说明为清晰的“照片可确认/仍待项目确认”小区块。未知工序、合金和结果不推断；如需更具体的工艺结论，先由工程团队确认。移动端将章节导航收进“本页内容”，让第一张关键图更早出现。

**验收标准**：每个技术说明能对应一张照片或已核实事实；首个内容屏能指出至少一个具体观察点；同一证据边界不在正文与侧栏重复；不新增无依据的公差、客户身份或交付成果。

**性质**：照片与说明分离、重复声明是观察；标注方式、图文节奏和更少的免责声明重复属于编辑及审美建议，不是交互故障。

### 5. 缩短手机长页，把工程判断信息前置并让锚点直接展示内容

**观察与证据**：390×844 下五轴能力页高度约 11,044 CSS px，14个产品示例全部展开；`Drawing, inspection & order planning` 位于约 y=8,882。点击上方 `Drawing & inspection` 可以跳转，但目标仍是收起状态，需要再点一次才能读正文，已实际复现。About 约15,251px，包含行业折叠项、应用插图、零件推荐、旧材料及大段照片档案；有档案快捷链接，但首屏没有覆盖主要公司信息的目录。截图 36、43、48、49，尺寸由本次 DOM 读取补证。

**客户影响**：顺序阅读时关键工程条件被产品图库推后；锚点解决了距离，却没有完成“展示答案”。长页连续重复内容降低阅读节奏，手机更明显。

**具体改法**：把工程范围和图纸/检验摘要移到示例前；能力页先展示3–4个代表实例，其余通过“查看全部14个”展开或进入目录，独立产品目录保留完整筛选。锚点指向折叠内容时自动展开目标，并保证标题不被固定页头覆盖。About 首先保留身份、团队、工厂与资质摘要，照片档案另设明确入口，或默认收起各年份；增加简短页面目录。

**验收标准**：手机能力页在产品网格前能看到工程条件；点击 Drawing & inspection 后正文直接可读、焦点可辨认；全部实例仍可到达；About 的身份、工厂、资质能通过首屏目录一次到达。390/768/1440 下不产生整页横向滚动，触控区域建议至少44px。

**性质**：锚点后仍需展开是本次确认的交互摩擦，并非死链接；页面长度与内容顺序是测量/观察；展示数量、目录形式和44px目标属于改进建议。

## 未验证范围

- 未核验ISO证书真实性、产能、交期、材料和实际加工/检测能力。建议所需事实必须另行核实。
- 未外发邮件、打开WhatsApp、上传文件或确认询盘收件；未点击草稿复制/保存后备按钮，因此仅确认其可见存在。
- 未穷尽35个产品、所有能力/案例/资源文章、筛选组合及全部菜单项。
- 未做真实手机设备、Safari/Firefox、网络限速、性能测量、完整控制台/网络错误审查。
- 未完成键盘全路径、屏幕阅读器、对比度、缩放和减少动态效果测试；不宣称WCAG合规。已看到表单标签、必填标记、搜索焦点框及无结果反馈。
- 768仅覆盖产品目录，不代表全站平板验收。长页主要覆盖代表模块，并非逐像素穷尽。
