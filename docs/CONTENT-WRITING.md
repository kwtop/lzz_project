# LZZ 网站内容写法

2026-10-18。用于正式网站新增内容和后续修改。布局、A 配色和图片规则按 DESIGN.md 的当前生效条款；本文约束怎么组织信息、怎么写句子。

## 先确定客户在这里要判断什么

首页帮助客户认出供应商、加工范围和下一步。服务页帮助判断零件是否适合这条加工路线。零件页讲清对象、接口和需要定义的要求。采购指南回答一个实际问题。新闻说明发生了什么，日期、人物和照片按原始资料保留。

先写下这个页面要回答的一个问题，再决定每个模块提供什么新信息。已经讲清的内容不要换一组词再讲一次。不同页面不强行采用同一套叙述结构。

## 借鉴 Penta 的内容组织

Penta 的首页从采购者的质量、交期和沟通问题切入，再讲服务和团队怎样处理；服务页把能力说明、加工过程、具体参数和常见问题分开；流程页让读者跟着订单走；采购文章直接解释报价差异及比较方法。

LZZ 沿用这种先帮助客户理解、再给细节的顺序。加工范围、公司资料、技术参数和承诺均来自 LZZ 自己的资料。客户评价、设备型号、认证、检验成绩、库存和交期不能从参考网站移植。

参考页面：[首页](https://www.pentaprecision.co.uk/)、[CNC milling](https://www.pentaprecision.co.uk/services/cnc-milling)、[How we work](https://www.pentaprecision.co.uk/how-we-work)、[Machining cost guide](https://www.pentaprecision.co.uk/resources/how-much-does-cnc-machining-cost)。

## 让公司说明自己的工作

服务介绍先说明 LZZ 做什么、检查什么，再告诉客户需要补充什么。不要让整页变成连续的 “Provide / Confirm / Agree / Define”。工程表格、采购清单和放行条件可以使用这些动词，因为它们确实在说明操作要求。

用具体的主体和动作。例如，说明我们怎样检查图纸、夹持、刀具可达性或检验要求。没有资料支持时，不写保证结果、节省比例、零缺陷、最快交付或任何客户成绩。

首页和入口页的主标题说明服务或主题，正文解释怎样处理。技术参数放在对应模块，重要适用条件与参数相邻。每个模块保留一个明确的主动作，链接名说明点进去能做什么。

## 写自然、具体的英语

采用专业供应商与采购、工程人员交谈的语气。可以使用 we 和 you，长短句按信息需要变化。先回答问题，再说明条件。短标题也要让人知道模块里有什么。

去掉没有增加信息的口号、段尾总结、三组硬凑的并列项、重复句首和无必要的破折号。不要为了显得有人情味而加入故事、人物反应或未经证实的经历。

用途段落直接说明这个应用需要哪些接口、环境或验收要求。避免反复使用 “Potential applications” 和 “Your drawing defines the requirements”；不能改写成已供货行业、真实客户或通过认证的案例。图片身份和制作来源留在内部注册表，公开呈现遵守 DESIGN.md 第 18 节及后续条款。正文不反复重述“照片无法证明什么”或来源审查过程。

牌号未知时写明需要指定的牌号、状态和材料记录。零件性能未知时写明测试条件和验收指标。真实工程因果或适用条件可以使用 can、may、if；不能把材料选项写成现货，把约定检验写成已通过测试，或为了肯定语气删除交期、公差的适用范围。

## 保留决定采购和验收的信息

公差、牌号、状态、尺寸、数量、日期、交期起算点、检验方法、批准责任和贸易条件都属于事实及适用条件，不能为了缩短句子而删掉。材料列表不等于现货清单；工厂照片不等于校准或零件检测记录。

有价值的技术表格保留原内容。信息太长时，可以分句、分组或调整呈现位置。数据、链接地址、锚点、查询参数、SEO 配置和结构化数据不能因改写而失去对应关系。

主询价入口使用 “Request a quote”。表单仍明确说明它准备本地邮件草稿；最终动作保留 “Prepare inquiry draft”，展示完整草稿、编辑和清除反馈。不能把入口文案改成已提交、已上传或已送达。

## 每次改写后的复查

先通读最终页面，检查每段是否增加了有用信息，语气是否符合页面任务，条件是否仍然完整。再对照原文，核对数字、专有名称和业务范围。最后在真实浏览器查看桌面与手机的标题换行、段落长度、卡片高度和按钮。

Humanizer 是编辑检查方法，不是检测作者或计算“AI率”的工具。关键词扫描只能发现待复看的句子，不能代替实际阅读。
