## 优先处理的四项

### 1. [P2] 服务页面的模块数量超过采购判断所需

**观察：** CNC Milling / 5-axis 首屏视觉高度相近，且使用同一多孔零件照片；首屏下面均有五项页内导航。页面 DOM 确认后续连续包含 Scope、零件实例、加工案例、三步服务说明、Drawing requirements、Inspection、Enquiry、Related resources、Related machining processes。Milling 列出了六个加工研究链接。六个链接是否在同一视口同时显示未单独测量。

**影响：** 对比两项服务时，用户要从相似页面里找差异；长页面又重复提示材料、图纸、检验和询价要求。具体加工能力的重点被通用采购说明稀释。

**建议：** 保留具体 Scope、三件零件和最多两条最相关的过程研究；把通用 Review/Machine/Finish 三步复述移到 How We Work。将 Drawing 与 Inspection 合为一个要求区，把通用 RFQ 六项列表收进一个清单入口。结尾保留一个询价区和一组最多三个相关出口。5-axis 优先选择已有五轴加工现场照片或现有叶轮照片，使服务差异更直观；保持照片事实边界。

### 2. [P2] 资源页的视觉包装和复述拖慢获取答案

**观察：** RFQ Checklist 手机首屏的大部分下半屏是说明性图片，直到底部才出现 Five essential requirements 的标题，五项要求还在下面。Shipping 先讲保护、标识和运输职责，后面五项 Checklist 再次覆盖同样话题；首图和文档区还有两张说明性图，实际包装档案放在更后面。Prototype 页桌面大标题出现单独一行的 `and`，接着展示 Validate/Approve/Repeat 摘要，正文再按相同三阶段展开。FAQ 顶部 Minimum order / Production 摘要与正文前两个问答重复。

**影响：** 清单类页面要求用户先看包装性画面和重复摘要，才能抵达可用的信息。技术采购用户的阅读速度下降；手机用户尤其要多滚动。

**建议：** RFQ 手机移除或显著缩小首图，让五项要求紧接简介；保留来源说明。Shipping 以五项清单作为主结构，相关解释放入各项下面，删独立重复章节；把现有真实包装档案提到清单附近。Prototype 用简洁标题和两列/手机两组的差异概览承接内容，删重复三阶段导航。FAQ 留顶部快速答案或正文对应问答中的一份，相关资源收敛成一组。

### 3. [P2] About 与 Quality 的低证明力内容占据过多篇幅

**观察：** About 具有三件真实零件实例，但其后还有十一项 Application families 折叠选项与 Explore application illustrations。公司发展五项横向叙述只有第一项标明成立年份。Quality 首个大内容区是一个显著的空白 inspection-record 卡片，明确标注 BLANK FORMAT / NO RESULTS；后续设备区再次使用同一 CMM 近景。当前证书编号、签发机构和有效期需邮件索取，页面没有公开显示这些字段。

**影响：** 有价值的原始现场证据与大量背景选项、空白示例竞争注意力。空白报告能解释交付格式，但不能替代质量记录；如此大的展示权重会产生更多阅读成本，未能同步增加可核查证据。

**建议：** About 保留公司简介、真实人员/工厂照片、三件具体零件与文件区；把十一行业选项和插图出口移入一个背景披露入口，五项发展叙述并入已有 Company background。Quality 把空白样表变成默认收起的格式预览，保留明确空白标注；用一个 Documentation 区承接报告、材料、finish 文件说明，删第二次 CMM 展示。供应商资格入口要紧凑可见，当前证书信息仍按实际资料提供，不能补写不存在的证据。

### 4. [P2] 文章和案例的开篇/收尾规则尚未统一

**观察：** 通用指南有展开的桌面 On this page；五轴案例的 On this page 默认收起，Photography & project scope 却默认展开，占据首张现场图片之前的重要区域。案例、一般资源、服务页底部组合了不同数量的 related parts、related capabilities、资源出口和询价模块。普通指南正文还穿插红色下划线链接，FAQ / Cases 的次级出口更多采用蓝色或黑色文字。

**影响：** 用户每换一个阅读页，要重新判断哪些是正文、哪些是证明范围、哪些是下一步。图片与工程说明的主路径会被多组出口打断；这些差异比品牌色本身更影响一致体验。

**建议：** 对阅读页统一为“简短范围说明 → 正文/现场图片 → 一组相关内容 → 一个主操作”。案例保留一行可见的事实边界，较长的 Photography scope 默认收起；不要删掉真实限制。桌面长文统一展开目录，手机统一折叠。统一独立次级出口的样式和措辞，将低关联的产品推荐和多组 Learn more 收敛。

## 可读性、信任与认知负荷

**截图观察：** 主体字号和段间留白整体可读，标题足够明显；工程信息用带标签的表格/定义列表比长宣传段落更容易扫描。主要可读性问题是段落与相关出口的总量，而非字体太小。Prototype 桌面的孤立 `and` 和多个阅读页的大标题会放大首屏占用。

**信任观察：** 真实工厂、人员和加工照片是当前最强的视觉证据。空白 inspection table、生成的包装/零件图和 company recognition 文件各有明确限定；不能把它们当作已发布检验结果或当前 ISO 证书。将已有真实证据提前、让限制简洁且可见，比加更多“可信”标识有效。

认知负荷：中等。Grouping、Visual hierarchy 与 Working memory 基本良好；主要失败项是 Chunking / Minimal choices。About 十一个并列行业入口是明显的选项墙；能力页五项页内导航和多种相关出口也超过四个选择，但有分组，严重性低于 About。不是每个超过四项的列表都需要改成新的控件。
