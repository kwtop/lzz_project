# DESIGN.md — Website Design Constitution（精简执行版）

> **目标：** 让现有网站的每个页面具有清晰的叙事逻辑、稳定的模块职责、自然的图文关系和统一但不模板化的视觉语言。
> **适用：** 首页、分类、产品、解决方案、案例、关于、指南和联系等网页的新建与改版。
> **使用：** 由项目 `AGENTS.md` / `CLAUDE.md` 明确要求读取。此文件不是自动生效的魔法指令，也不是固定页面模板。

## 0. 优先级与底线

执行优先级：**用户明确要求与已确认方案 → 业务真实性、功能、安全与 SEO → 页面叙事与模块职责 → 图片和构图 → 字体与细节。**

- **必须：** 保留真实产品事实、关键参数、必要文本、有效内链、询盘路径、SEO/GEO 与无障碍能力；不得编造认证、客户、工厂、车辆配置、交付和业绩。
- **必须：** 优先复用项目现有且已确认的设计规范、字体、色彩、组件及图片；不覆盖无关改动，不擅自换技术栈、URL 或部署生产。
- **原则：** 规则服务于用户理解，不为了凑模块、凑图片或凑视觉变化而牺牲真实性和可用性。

## 1. 首先设计用户的阅读路径，而不是先写 CSS

改动每个页面前，明确回答四个问题（内部简答即可）：

1. **谁在看？** 目标访客是谁，处于什么决策阶段？
2. **为什么来？** 此页最需要解决的一个核心问题是什么？
3. **按什么顺序理解？** 用户先需要知道什么，再需要验证什么，最后应采取什么行动？
4. **凭什么相信？** 哪些真实图片、数据、规格、案例或来源能支持关键结论？

默认叙事顺序：**快速识别 → 理解/筛选 → 判断适配 → 验证可信 → 下一步行动。** 不是要求每页复制五个模块；可按具体任务调整顺序、合并或拆分。

**禁止：** 先拼凑现有组件，再用大量标题、营销短句和卡片把页面填满。

## 2. 页面结构：默认 4–7 个有职责的核心模块

- **默认：** 常规展示型页面组织成 **4–7 个核心叙事模块**，用来维持稳定、舒适的阅读节奏。
- **计数方式：** 只计算承担独立信息任务的主要内容章节；导航、页脚、悬浮询盘、面包屑、独立 FAQ 条目和产品卡片项不各自计作一个模块。
- **一模块一职责：** 每个模块回答一个明确的用户问题，有一个主要视觉焦点和必要的信息；不能重复相邻模块的职责。
- **允许例外：** 联系页可更短，深度指南/法规/技术文档可更长；参数表、FAQ、筛选器按实际使用需要保留。不要为了强行符合数量而删信息或制造无用模块。
- **同类型页面：** 核心信息顺序相对稳定，便于阅读与维护；不同产品、案例和场景的图片、信息密度与构图应因内容而变化。

### 页面类型：叙事骨架（按需选用，不是强制模板）

| 页面类型 | 典型叙事顺序 | 建议核心模块 |
| --- | --- | --- |
| 首页 | 我们是谁 → 有哪些产品 → 适用于哪里 → 为什么可信 → 如何合作 → 询盘 | 5–6 |
| 分类页 | 类别定位 → 产品查找/比较 → 如何选型 → 配置/适用范围 → 获取建议 | 4–5 |
| 产品详情 | 产品是什么 → 适用于谁 → 关键参数/配置 → 实物细节/应用 → 可信证据 → 询价 | 5–6 |
| 解决方案 | 场景/问题 → 解决思路 → 推荐产品 → 适配边界与证据 → 联系 | 4–5 |
| 案例页 | 真实需求 → 方案选择 → 执行/发货证据 → 可核实结果 → 相关产品/下一步 | 4–5 |
| 关于/工厂 | 企业定位 → 真实设施/团队 → 流程与能力 → 可核实证明 → 联系 | 4–5 |
| Blog/指南 | 直接回答 → 解释/步骤 → 图表/证据 → 来源/FAQ → 相关阅读/产品 | 随内容深度调整 |
| 联系/询盘 | 明确行动 → 联系/表单 → 消除疑虑 | 可少于 4 |

**模块保留标准：** 如果它不能让用户更容易找到信息、理解产品、判断适配、验证可信或完成下一步，应优先合并、缩短、降权或删除。

## 3. 图文共同构图：先定视觉表达，再排文字

### 3.1 图片不是“填空素材”

每个核心模块按顺序决定：**要解释的事实/问题 → 最合适的视觉证据或表达 → 图片比例与主体位置 → 标题和正文位置 → 交互/CTA。**

- 展示型页面应由**具有信息价值的真实图片、示意图或数据图表**承载大部分视觉叙事；“约 2/3 主要模块具有有效视觉”可作为检查信号，**不是硬配额**。
- 不鼓励连续两个大段纯文字展示模块；优先合并重复文字、补充相关视觉或调整构图。长文章、法规、技术参数等允许文字主导。
- 常规视觉模块的文案先尝试 **1 个明确标题 + 1–3 句有用说明**，更细的参数与采购知识放在适合阅读的模块中，不为“极简”删除有价值内容。
- 禁止只有一张小图配大量解释文字，也禁止无关大图占满屏幕却不能支持信息表达。

### 3.2 每张主要图片必须做出一个行动决策

| 决策 | 什么情况下使用 | 执行要求 |
| --- | --- | --- |
| **KEEP** | 图片真实、准确、清晰且构图合适 | 直接保留，必要时做响应式裁切 |
| **ENHANCE** | 素材真实有用，但光线、色调、清晰度或画幅不理想 | 优先非生成式裁切/调色；有 ImageGen 能力时可审慎编辑并核对原图事实 |
| **GENERATE** | 缺少非证据性的概念/应用辅助视觉 | 有 ImageGen 能力时实际生成并检查，明确其示意属性，不冒充真实业务 |
| **NEED REAL ASSET** | 缺少真实车辆、客户、工厂、证书或项目证据 | 寻找真实素材；找不到则标注待补、调整布局，**不得用 AI 假图代替证据** |

生成/修图前简要指定：**用途、主体、事实边界、构图方向、留白位置、光线/色调、桌面与移动端裁切、禁止出现的错误细节**。检查结果后才接入。工具不可用时不得声称已经生成；继续完成可做的裁切、排版和素材整合。

### 3.3 布局根据内容变化，不靠随机花样

可选择：**大幅主图、图上文下、非对称图文、主次图片组合、产品网格、真实过程照片、规格/对比表、简洁 CTA**。

- **统一**字体、颜色、间距、按钮与对齐逻辑；**变化**图片大小、文字位置、背景明暗、模块比例和构图。
- 不连续机械复制“三列卡片 → 左图右文 → 三列卡片”；也不为了求变化而牺牲产品的可比较性、阅读顺序或移动端表现。
- 图片和文字必须互相解释；先看图能建立直觉，再读文字能得到有用的事实或决策信息。
- 桌面首屏优先有明确视觉主角；移动端允许改为图上文下、重新裁切或换合适的真实素材，而不是单纯缩小桌面版。

## 4. 视觉基础：少而稳定的设计规则

优先复用项目已经确认的 Design Tokens。没有现成规范时，以下只作**调试起点**，不得无脑套用：

- **Typography：** H1 / H2 / H3 / 正文 / 辅助五级足够；桌面正文通常 16–18px，行高约 1.5–1.7；英文长正文约 60–75 字符宽，标题认真处理换行。
- **空间：** 主内容容器可从 1200–1360px 起试；模块间距按关联性调整，让需要一同理解的内容靠近、主题转换处留白更大。
- **图片：** 主图可大胆放大，图片组要有视觉主次；保证车辆/产品主体不会被裁坏，色调协调但不过度 AI 化。
- **视觉节奏：** 大与小、疏与密、浅与深适当交替；拒绝全站纯白加黑字却没有重点，也拒绝过量渐变、阴影、胶囊标签、箭头和装饰小字。
- **语义与性能：** 保持可读文本、正确标题层级、Alt、响应式尺寸、键盘操作、必要 SEO 元素、合理加载与 CTA 行为。

## 5. 强制执行流程（比增加形容词更重要）

1. **读项目：** 读取 `AGENTS.md`、本文件、已确认方案、页面内容、真实素材和现有样式；保留可回退基线。
2. **先定结构：** 给每个待改页面列一份简短的**模块决策表**：`模块顺序 | 用户问题 | 模块职责 | 核心事实 | 视觉形式 | 图片动作`。检查是否存在重复职责、缺失问题与不合理跳跃。
3. **先定图片：** 针对每个主要视觉决定 KEEP / ENHANCE / GENERATE / NEED REAL ASSET；有合适图片先用，不能为了生成而生成。
4. **再写代码：** 围绕选定素材设计布局；优先调整模块顺序、文案密度和图片表现，不无故重构业务功能。
5. **先做样板：** 批量改版时每种主要页面类型先完成一页；确认设计方法可靠后自动推广到同类页面，不需要逐页打断用户。若明确要求先审批，则按审批节点执行。
6. **实际验收：** 至少查看 **1440px 桌面端 + 390px 移动端整页截图**。发现布局单调、文字堆积、图片不协调、阅读顺序混乱或重要信息被弱化，必须继续修正。不要把构建成功当视觉验收。
7. **回归交付：** 检查产品数据、询盘入口、导航/内链、SEO/GEO、响应式、性能与基本功能；交付截图、主要修改和待补真实素材清单。不擅自部署。

## 6. 五问验收：不符合就不是完成

1. **一眼看懂：** 3–5 秒内能识别页面主题与核心价值吗？
2. **顺着读懂：** 模块是否按用户自然提问顺序展开，且每个模块只负责一件主要事情？
3. **图文相互支持：** 重要图片是否准确、有用、好看？是否还有大片无意义文字或图片仅作装饰？
4. **整页有节奏：** 是否在视觉上有主次、有变化、有合理留白，且手机端依然自然？
5. **真实可行动：** 参数、案例、来源与业务信息是否可靠？能否容易找到产品细节与下一步操作？

**最终原则：先让人理解，再让人喜欢；用图片降低理解成本，用文字提供准确信息，用布局引导阅读。统一的是设计逻辑，不是每个页面的外观。**
